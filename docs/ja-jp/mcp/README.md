# MCP の統合

TayPE は、AI アシスタントをツールやアプリケーションに接続するためのオープン標準であるモデル コンテキスト プロトコル (MCP) 上でエンジンを公開します。すべての MCP クライアント (Claude Desktop、カスタム エージェント、または独自のツール) は、実行中の TayPE インスタンスに接続し、プログラムで制御できます。

これは、DAW と対話できることを意味します。トラックの追加、クリップの移動、レベルの設定、プラグインのロード、録音の開始を、AI アシスタントを介した自然言語を通じて、または独自のコードからの直接ツール呼び出しを通じて行うことができます。

## 仕組み

TayPE には、MCP クライアントと実行中のアプリの間のブリッジとして機能する `taype-mcp` というコンパニオン プロセスが付属しています。ブリッジは、一方の側で標準 MCP (JSON-RPC 2.0 over stdio) を通信し、もう一方の側で TayPE のエンジンと通信します。

```
Your MCP Client (Claude Desktop, etc.)
    |
    |  JSON-RPC 2.0 over stdio
    v
taype-mcp (bridge process)
    |
    |  Internal protocol over localhost
    v
TayPE (running app)
```

## 接続中

### クロードデスクトップ

TayPE で、**[ツール] > [Claude Connector のインストール]** に移動します。これにより、TayPE に接続するように Claude Desktop が自動的に構成されます。手動で編集する必要はありません。インストール後に Claude Desktop を再起動します。会話を開始する前に TayPE を実行する必要があります。

### Codex

TayPE で、**[ツール] > [Codex Connector のインストール]** に移動します。これにより、Codex に TayPE がローカル MCP サーバーとして追加されます。手動で編集する必要はありません。インストール後に Codex を再起動します。セッションを開始する前に TayPE を実行する必要があります。

### 手動構成

自分で設定したい場合、または別の MCP クライアントを使用している場合は、TayPE を MCP 構成に追加します。

Claude Desktop の場合:

```json
{
  "mcpServers": {
    "taype": {
      "command": "/Applications/Taype.app/Contents/MacOS/taype-mcp"
    }
  }
}
```

Codex の場合:

```toml
[mcp_servers.taype]
command = "/Applications/Taype.app/Contents/MacOS/taype-mcp"
```

### 他の MCP クライアント

MCP stdio トランスポートをサポートするクライアントは、`taype-mcp` をサブプロセスとして起動することで接続できます。ブリッジはハンドシェイクを処理し、利用可能なツールをすべて公開します。

クライアントが不正な形式の JSON を送信すると、ブリッジは標準の JSON-RPC 解析エラー (`-32700`) を返します。 JSON は有効ですが、有効なリクエスト オブジェクトではない場合、ブリッジは `-32600` (`Invalid Request`) を返します。

## 得られるもの

接続時に、MCP ハンドシェイクは次を返します。

- **サーバー情報** - アプリ名とバージョン
- **ツール リスト** - 利用可能なすべてのツール (以下のサブページに記載されています)
- **手順** - これらのドキュメントへのリンクを含む前文と、アクティブなドキュメント
スタジオ技術者のパーソナリティが設定されている場合 ([性格](personalities.md) を参照)

## コンセプト

### 編集を停止する

TayPE は厳密な「編集を停止する」ルールに従います。構造の変更 (トラックの追加、プラグインのロード、クリップの削除) は、トランスポートが停止している場合にのみ発生します。再生は聴いたり演奏したりするためのものです。これにより、エンジンが予測可能になり、他の DAW をクラッシュさせるような競合状態が防止されます。

停止したトランスポートを必要とするツールを再生中に呼び出すと、エラーが返されます。 `status` ツールは、現在のトランスポート状態を示します。

### 取引

複数の変更を 1 回の元に戻す手順として行う必要がある場合は、`tx_begin` および `tx_commit` を使用してそれらの変更をトランザクションでラップします。トランザクションがアクティブである間、UI は構造的な編集をロックして、人間のユーザーが編集シーケンスを妨害するのを防ぎます。トランザクションは短時間であることを目的としています。トランスポートおよび記録コマンドは、コミットまたは中止するまで拒否されます。

トランザクション中に接続が切断された場合、TayPE は自動的に中止され、トランザクション前の状態にロールバックされます。ユーザーは、「編集」メニューから手動でロックを解除することもできます。 `tx_commit` が成功すると、結果として生じるリールの動作状態が変更された場合でも、その状態がすぐに保持されます。

### フィードバックと問題の報告

`submit_feedback` ツールを使用すると、ユーザーに代わってバグ レポートやフィードバックを提出できます。システム情報 (バージョン、OS、CPU、オーディオ構成、プラグイン、ライセンス層) を収集し、TayPE チームに投稿します。

送信する前に、送信されるすべてのものをユーザーに示し、明示的な承認を得る必要があります。同意なしにマシンを離れることはありません。
